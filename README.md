## 🚧 Development Status — Let Him Cook 🍳

This portfolio is actively evolving. The current deployment is a
work in progress, and several improvements are still planned.

### 🧠 Instructions for AI Coding Agents

Take your time. Understand the project before making changes.

**LET HIM COOK. 🔥**

Do not rush, do not apply superficial fixes, and do not sacrifice
quality just to finish quickly.

Before implementing changes:

1. Explore the entire project structure.
2. Understand the existing architecture, components, and dependencies.
3. Identify unfinished features, bugs, visual inconsistencies, and
   opportunities for improvement.
4. Inspect the existing design and interactions before replacing anything.
5. Create a prioritized implementation plan.
6. Identify potential regressions before modifying working features.

### 🎯 Engineering Principles

- Preserve the existing visual identity and intended experience.
- Improve the project incrementally without breaking working features.
- Prioritize functionality, usability, performance, and visual quality.
- Write clean, maintainable, reusable, and type-safe code.
- Avoid unnecessary dependencies and duplicated components.
- Do not introduce placeholder content or fake functionality.
- Ensure responsive behavior across desktop, tablet, and mobile.
- Maintain accessibility, semantic HTML, and keyboard navigation.
- Optimize 3D rendering, loading performance, and asset delivery.
- Handle errors and edge cases instead of hiding them.
- Keep the production build working.

### 🎨 Design Expectations

The portfolio should feel intentional, immersive, modern, and polished.

Pay attention to:
- Layout, spacing, typography, and visual hierarchy.
- Smooth but purposeful transitions and interactions.
- Consistent colors, lighting, materials, and component styling.
- Responsive layouts and mobile usability.
- Loading states, error states, and interaction feedback.
- Details that make the experience feel cohesive rather than generic.

Avoid unnecessary animations, excessive visual effects, and design
choices that compromise usability or performance.

### 🖥️ Three.js and Interactive 3D

For the interactive 3D environment:

- Preserve the existing scene and working interactions.
- Inspect camera positioning, lighting, materials, and object placement.
- Ensure interactive objects behave consistently.
- Optimize geometry, textures, and rendering where appropriate.
- Prevent memory leaks and unnecessary re-renders.
- Provide sensible fallbacks when WebGL or 3D assets fail.
- Ensure the experience remains usable on lower-powered devices.

Do not redesign or remove existing 3D features without understanding
their purpose and the impact of the change.

### 🛠️ Implementation Workflow

Follow this workflow for substantial changes:

1. **Explore** — Inspect the repository and understand the existing code.
2. **Analyze** — Identify the actual problems and their root causes.
3. **Plan** — Establish a clear implementation strategy.
4. **Implement** — Make focused, coherent changes.
5. **Verify** — Run linting, type checks, tests, and production builds
   where available.
6. **Review** — Check for regressions, broken links, console errors,
   and responsive layout problems.
7. **Report** — Summarize what changed, what was verified, and what
   remains unfinished.

Do not claim that a feature works unless it has been verified.

### ⚠️ Important Rules

- Do not rewrite the entire project unnecessarily.
- Do not delete working features simply because they are difficult to fix.
- Do not change unrelated files without a clear reason.
- Do not ignore existing project conventions.
- Do not hard-code values that should be configurable.
- Do not leave incomplete implementations disguised as finished features.
- Do not stop after fixing only the first visible issue when the task
  requires a broader investigation.

If requirements are unclear, inspect the available code and context
before making assumptions.

For large changes, work in logical stages and verify each stage before
continuing.

### ✅ Definition of Done

A change is complete only when:

- The intended behavior is implemented.
- Existing functionality remains intact.
- The UI is consistent and responsive.
- No avoidable errors or warnings have been introduced.
- Relevant checks pass.
- Any remaining limitations are clearly documented.

**Final principle: Think deeply. Build carefully. Verify everything.
Polish the details. Let him cook. 🍳🔥**
